Yoph Tool Toolbar Style Guide
=============================

Scope
-----
This guide applies to every Yoph tool page, including AI. The home page uses the same shared app selector and visual tokens but does not need an editor toolbar.

Core visual rules
-----------------
- Use a white top toolbar row and a light gray lower row (#E2E8F0) for all tool pages.
- Keep toolbars flat, minimal, and aligned with square corners and 1px borders (#CBD5E1).
- Keep the page title or document title on the far left of the top bar.
- Keep the app selector in the shared action area at the far right of the top row or within the AI footer toolbar.
- Keep the save state icon aligned at the far right of the bottom toolbar, without a visible text label.
- Use the green accent (#059669) and darker green border (#047857) for primary actions only.

Structure
---------
- Prefer a two-row structure on tool pages when the page has a title and more than one action group.
- The upper row holds title input, view toggles, file controls, and shared app actions.
- The lower row holds the working controls for the tool itself, such as zoom, new item actions, or formatting groups.
- If a tool has a dedicated lower control bar already, keep it visually consistent and let the shared Yoph shell wrap it in the light gray toolbar treatment.
- Keep action groups aligned left-to-right with consistent spacing; avoid drifting controls or mismatched heights.
- Maintain the same page selector on every tool page so navigation feels stable and predictable.

Sizing and spacing
------------------
- Toolbar row minimum height: 40px (2.5rem).
- All toolbar inputs, buttons, selects, and grouped controls: 32px high (2rem).
- Toolbar vertical padding: 8px (0.5rem).
- Toolbar horizontal padding: 12px (0.75rem).
- Gap between toolbar controls: 4px (0.25rem) to 8px (0.5rem), depending on the group.
- Use 1px borders with #CBD5E1 on white controls and light gray controls.
- Use 1px category separators in #CBD5E1 on the lower light-gray row.
- Keep controls aligned vertically inside the same row.
- Use square corners; do not use rounded toolbar controls.
- Keep focus outlines visible and use the shared green accent for keyboard focus.

Text and controls
-----------------
- Toolbar text should be concise and live within the control itself. Remove standalone labels where possible.
- Use the existing page action IDs so page behavior stays compatible.
- Use the existing Paint trash-can icon for Clear and keep the shared clear action visually consistent.
- The Apps control is a square grid button at the far right of the toolbar. It should remain consistent across all pages.
- The save-state icon uses Material Symbols Outlined `check` when clean and `progress_activity` when actively saving.
- The save-state icon stays 32px square, borderless, and has no visible text label.
- If a tool already uses a custom action suite, do not replace its behavior; only normalize spacing, alignment, and visual weight.

Responsive behavior
-------------------
- At narrow widths, controls may wrap inside their row.
- The title field may occupy a full row and use the available width.
- Preserve the left/right anchoring priorities when controls wrap.
- The page selector and save indicator should remain visible and correctly aligned, even in compact layouts.

Implementation notes
--------------------
- The shared Yoph shell is responsible for the app selector and save-state indicator across tool pages.
- Each page may still keep its own tool-specific controls, but the surrounding shell should remain visually uniform and align button groups cleanly.
- AI uses the same shared app selector and square save-state treatment, but it lives in the bottom footer toolbar instead of the top header.
- The lower toolbar should remain light gray in all cases, including the AI page footer.

Final rule
----------
The suite feels clean when every tool page shares the same shell: white top bar, light gray lower rail, consistent control sizing, square borders, and a single app selector that stays in place on every page.
