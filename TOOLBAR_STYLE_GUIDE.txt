Yoph Tool Toolbar Style Guide
=============================

Scope
-----
This guide applies to every Yoph tool page: AI, Calendar, Paint, Planner, Timeline, and Word. The home page shares the same visual tokens and app selector but does not need an editor toolbar.

Shared visual rules
-------------------
- Keep the existing restrained, flat Yoph look; do not introduce a new visual theme.
- Toolbars use square corners, 1px borders (#CBD5E1), Inter/system UI typography, and visible green keyboard focus (#059669).
- Use a white top toolbar row and a light gray lower toolbar row (#E2E8F0) on tool pages. The AI composer footer is also light gray.
- Keep controls within each toolbar row vertically centered and grouped with consistent 4–8px gaps.
- Toolbar buttons, selects, and inputs are normally 32px high (2rem). Preserve larger in-canvas/editor controls where required by the tool.
- Reserve green (#059669) with dark green border (#047857) for primary actions. Keep secondary controls neutral.
- Keep the app selector consistent: square 32px grid button, accessible label, expanded state, and current page marked in its menu.
- Keep save state as a borderless 32px icon, showing `progress_activity` while saving and `check` when saved; expose the state through its accessible label/title.

Page-specific toolbar structure
-------------------------------
- Calendar, Planner, Paint, and Timeline: title and file actions stay in the white top row; tool/view/zoom controls stay in the light gray lower row. Preserve each page's existing action IDs and behavior.
- Word: title and file actions stay in the white top row; the formatting ribbon is the light gray lower row. Keep ribbon groups aligned and horizontally scrollable when needed.
- AI: keep the chat workspace flexible and scrollable. The light gray footer is a compact composer row plus a separate shared-app/save row. Pending attachments wrap above the composer. Do not absolutely position selector/save controls over the prompt or attachment tray.
- Home: keep the tool cards and shared navigation visually consistent with the same tokens.

Sizing and responsive behavior
------------------------------
- Toolbar rows have a 40px minimum height (2.5rem), with 8px vertical and 12px horizontal padding on desktop.
- Keep controls aligned to a common center line and avoid extra margins that cause groups to drift.
- At narrow widths, let groups wrap without clipping; keep the app selector and save icon visible. AI prompt input must shrink with `min-width: 0`, while the file, clear, and send actions retain usable tap targets.
- Maintain clear focus-visible outlines, readable contrast, and reduced-motion support.

Implementation notes
--------------------
- `assets/js/yoph.js` owns the shared selector, save-state indicator, and generated toolbar shell; it must not duplicate existing page actions.
- `assets/css/yoph.css` owns common design tokens and toolbar alignment. Page CSS should focus on tool-specific workspace behavior.
- Do not use blanket selectors that unexpectedly resize canvas controls or modal buttons. Scope shared toolbar rules to the toolbar classes.
- Preserve existing tool behavior and action IDs while making alignment and styling changes.

Final rule
----------
Every page should feel like part of the same suite: stable navigation, aligned controls, a white upper rail, a light gray lower rail, and no unnecessary redesign.
